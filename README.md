# 환승로그

**기다리는 시간도, 여행이 되도록.**

인천공항 환승객이 가용시간과 취향에 맞춰 짧은 한국 여행을 만들고, 비·도착 지연·교통·현재 위치에 따라 일정을 다시 설계하는 반응형 웹 앱입니다.

공개 사이트: **https://hwanseung-log.jum4769.workers.dev** (Cloudflare, 2026-09-21 배포). 관광·항공·택시 API와 ODsay Web 대중교통 연결을 확인했습니다. ODsay에는 이 공개 도메인만 등록했으며 기존 로컬 Server 설정도 유지합니다.

## 실행

Node.js 22 이상에서 외부 패키지 설치 없이 실행합니다.

```sh
npm start
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다. Windows에서는 `실행하기.cmd`를 실행해도 됩니다.

```sh
npm test
npm run build
```

`dist/`는 정적 호스팅 결과물입니다. Cloudflare 기본 배포는 `wrangler.jsonc`로 `public/`와 Worker를 함께 올립니다. 모든 화면, 계획 계산, 저장, 공유, 백업은 정적 호스팅에서도 동작합니다. 관광·항공·교통 API와 최신 정보 일정 업데이트는 Cloudflare Worker 또는 로컬 `server.mjs`에서 제공합니다. 정적 파일만 배포하면 API 연결 버튼이 예시 정보 유지 상태를 안내합니다. 날씨는 브라우저에서 Open-Meteo에 직접 요청합니다.

## 실제 데이터 연결

1. `.env.example`을 `.env`로 복사합니다.
2. 공공데이터포털에서 승인받은 한국관광공사 국문 관광정보 API 키를 `TOUR_API_KEY`에 설정합니다.
3. 서버를 재시작한 뒤 장소 탐색의 화면을 엽니다. 사진·주소를 자동 조회하며 장소 상세에서 운영정보를 확인할 수 있습니다.
4. API 응답이 성공했을 때만 연결 상태가 표시됩니다.

키는 서버에서만 사용하고 브라우저에 전달하지 않습니다. 인코딩·디코딩 키 입력을 지원합니다. 검색 응답을 메모리에만 표시하며 관광공사 원본 데이터를 데이터베이스나 서비스 워커에 복제하지 않습니다. 키가 없거나 요청이 실패하면 예시 상태를 유지합니다. 키 설정 후 실제 승인·응답 확인은 별도로 필요합니다.

- 기본 URL: `https://apis.data.go.kr/B551011/KorService2`
- 장소 조회: `searchKeyword2` — 8개 큐레이션 장소명 기준 요청
- 서버 상세 엔드포인트: `/api/detail?id=CONTENT_ID&type=12또는14` → `detailCommon2` + `detailIntro2`
- 제공 정보: 관광공사 사진·주소·장소 소개·운영시간·휴관일·요금 원문·문의처·조회 시각. 응답에 없는 항목은 제공 정보 없음으로 표시
- 출처: ⓒ한국관광공사

## 계산 범위와 한계

이 앱은 항공권 예약 서비스나 입국 자격 판정 서비스가 아닙니다. 항공편 비교는 사용자가 입력한 수치로 계산합니다. 기본 장소의 운영시간·입장 비용·대중교통 및 택시 이동시간은 **시연을 위한 고정 추정값**입니다. 항공편 상태와 현재 교통 경로를 실제 조회할 수 있습니다. 오늘의 당일 일정에서는 선택 코스의 모든 이동 구간과 항공편을 조회하고 변경 전후 비교 후 적용할 수 있습니다. 관광공사가 제공한 휴관·공휴일 예외 문구는 장소 상세에 그대로 표시합니다. 임시 휴관과 잔여 티켓 수를 실시간으로 검증하거나 원문을 자동 해석해 계획값을 바꾸지는 않습니다. 방문일의 실제 운영 여부는 제공기관 안내를 확인해야 합니다.

전체 환승시간에서 입국 준비, 수하물 추가시간, 도착 지연, 출국 전 준비, 추가 여유, 터미널 추가 여유를 뺍니다. 후보별 왕복 이동·관람·개장 대기를 계산하고 예산·복귀 기준·정기 휴관·날씨 조건으로 필터링합니다. 같은 지역에서 최대 2개 장소를 묶어 취향 점수로 정렬합니다. 비와 눈을 선택하면 야외 장소를 제외합니다. 외부에서 재계획할 때는 현재 시각·장소와 남은 예산을 기준으로 같은 지역을 탐색합니다.

복귀 알림은 페이지가 열려 있을 때만 확인하는 화면 알림이며 백그라운드 푸시가 아닙니다. 캘린더 파일에는 복귀 출발 15분 전 알림이 포함되며 실제 알림 처리는 가져온 캘린더 앱에 따릅니다. 입국·탑승·복귀 시각을 보장하지 않습니다.

날씨는 선택한 날짜의 인천 예보를 Open-Meteo에서 요청합니다. 예보 범위 밖 날짜나 연결 실패를 별도로 안내합니다. 주변 모든 지역의 실황을 대표하지 않습니다.

## 추가 API 연결 (2026-09-21)
- 인천공항: `AIRPORT_API_KEY`. `/api/flights?flight=7C1615&direction=departure`에서 한국시간 당일 운항정보 조회. 게이트와 예정/변경 시각을 표시하며 기존 복귀 마감을 자동 연장하지 않습니다.
- ODsay: 로컬은 `ODSAY_API_KEY`에 Server 플랫폼 인증키를 설정합니다. Cloudflare는 별도 `ODSAY_WEB_PUBLIC_KEY`와 공개 도메인 등록이 필요합니다.
- Kakao Mobility: `KAKAO_REST_API_KEY`에 REST API 키가 필요합니다. 계정의 이용 조건과 호출 허용 IP를 확인하세요.
- `/api/directions`는 origin/destination(경도,위도), mode(transit/car)를 받습니다. 사용자가 선택한 장소와 T1/T2 기준 이동시간을 조회합니다. ‘지금 정보로 일정 업데이트’에서 전체 코스의 구간별 시간을 계산에 반영하고 비교 후 적용합니다.
- 프런트엔드의 나만의 여행/경유편 비교 화면에서 항공편 조회와 이동 경로 조회를 사용합니다. 날씨는 기존 Open-Meteo 연결을 사용합니다.
- 서버 키는 로컬 `.env` 또는 Cloudflare Secrets에 저장하고 프런트엔드·dist·소스 배포 압축파일에 포함하지 마세요. ODsay Web 공개 키만 등록한 도메인의 브라우저 호출에 전달됩니다.
- 정적 파일만 배포하면 API 기능은 포함되지 않습니다. Cloudflare 기본 배포에는 Worker API가 함께 포함됩니다.
- 공식 문서: https://lab.odsay.com/guide/releaseReference / https://developers.kakaomobility.com/guide/navi-api/directions


## 일정 갱신과 공개 배포 준비

나의 환승에서 코스를 선택하면 **지금 정보로 일정 업데이트** 버튼이 나타납니다. 오늘 출발하는 당일 일정에 한해 왕복·장소 간 이동시간과 요금을 확인합니다. 도착·출발 편명을 입력하면 항공편도 함께 확인합니다. 편명은 선택사항입니다. 미리보기를 확인한 뒤 적용하면 변경 기록과 확인 시각을 남깁니다. 오류·한도 초과·불가능한 코스는 기존 일정을 유지합니다. 출발 지연으로 복귀 마감을 연장하지 않습니다.

[공개 배포 안내](DEPLOYMENT.md)는 Cloudflare Workers + Static Assets를 기본 대상으로 합니다. `wrangler.jsonc`와 `cloudflare/`에 API 및 영구 호출 장부를 구성했습니다. `Dockerfile`, `compose.yaml`, `Caddyfile`은 별도 VPS를 선택할 경우에만 쓰는 대안입니다. 로컬·VPS는 단일 Node 프로세스 기준 장부를, Cloudflare는 Durable Object 장부를 사용해 방문자별 요청 제한과 일일 API 상한을 제공합니다.

배포 압축파일은 `python scripts/package-release.py`로 만듭니다. 포함 파일 목록을 제한하고 로컬 API 키가 발견되면 생성하지 않습니다. `.env`, `.dev.vars`, 인증 정보, Git 기록, 호출 장부는 제외됩니다. 원본 응답을 서버에 캐시하지 않습니다. Cloudflare 공개 HTTPS 검증은 완료했고, 선택 대안인 Docker 컨테이너 실행은 별도로 검증하지 않았습니다.


## Cloudflare 배포

`npm ci` → `npm run cf:check`로 확인한 뒤 계정 인증 후 `npm run cf:deploy`로 배포합니다. 화면과 API를 하나의 Worker로 배포합니다. API 키는 Cloudflare Secrets에 설정하며 기존 로컬 `.env`가 자동으로 업로드되지는 않습니다.

**ODsay만 별도의 Web 플랫폼 키가 필요합니다.** 기존 `ODSAY_API_KEY`는 로컬 Server 키로 유지하고, Cloudflare에는 등록한 도메인에서 쓰는 `ODSAY_WEB_PUBLIC_KEY`를 설정합니다. 브라우저에서 ODsay로 직접 호출하는 공식 인증 방식을 사용하며 Worker에서 출처를 위조하지 않습니다. 자세한 절차와 한도는 DEPLOYMENT.md에 있습니다.

## 1.1.1 심사 기준 반영 개선

관광공사 검색 결과는 장소명·콘텐츠 유형·좌표를 함께 대조해 8개 큐레이션 장소에 연결합니다. 동명 식당과 행사를 관광지로 오인하지 않습니다. 장소 상세는 운영시간·휴관일·요금·문의처와 조회 시각을 표시하고 일정 계산용 추정값과 구분합니다. 조회 결과는 현재 화면의 메모리에만 보관합니다.

일정의 복귀 보드는 계획상 출발·공항 도착 기준 시각과 교통정보 조회 상태를 표시합니다. 미래 여행, 예시 일정, 복귀 임박, 기준 시각 경과를 구분합니다. 당일 및 익일 출발 환승의 재계획에서 이미 지난 시각을 출발 시각으로 추천하지 않도록 보강했습니다. 날씨 예보에 비 가능성이 있을 때 대체 코스 비교로 이어지는 버튼을 제공합니다.

## 1.2.2 공모전 데모

기본 주소와 /#home은 기존 여행 소개 화면을 보여줍니다. 공모전 데모는 별도 버튼이나 /#demo 링크로 선택해 실행합니다. 공유용 주소는 `https://hwanseung-log.jum4769.workers.dev/#demo`입니다. 기본 여행, 비, 비와 90분 도착 지연, 15:30 문자박물관 출발 후 공항 복귀의 네 가지 상황을 비교·적용할 수 있습니다. 이 시나리오는 외부 API 호출 없이 실행하며 실제 관광정보·교통 조회는 별도 동작입니다.

데모와 개인 여행은 서로 다른 브라우저 저장 공간을 사용합니다. 기존 개인 일정이 있으면 기본 모드를 유지하며, 내 일정으로 시작하기를 누르면 개인 여행을 복원합니다. 새 개인 여행의 입국 확인은 미확인으로 시작합니다. 데모에서는 여행 시각 경과 알림을 보내지 않습니다.

자동 검증 48개에는 홈 기본 진입과 데모 직접 링크, 기존 개인 일정 보호, 저장소 오류 시 메모리 유지, 날짜 경계에 걸친 데모 시나리오 재현을 포함합니다.

## 공모전 최종 문서와 복원

`docs/`에 팀명 **환승로그**, 최종 지정과제 **1번**을 반영한 기능설명서 PDF와 편집 가능한 PowerPoint 원본을 보관합니다.

다른 컴퓨터에서 저장소를 내려받은 뒤 `npm ci`로 의존성을 설치합니다. 로컬 API 조회가 필요하면 `.env.example`을 참고하여 별도로 `.env`를 만들고 본인의 인증키를 입력합니다. Cloudflare 배포 인증과 Secrets 설정은 `DEPLOYMENT.md`를 따릅니다. 실제 인증키, `.env`, `.dev.vars`, 로그인 정보와 `node_modules`는 Git에 포함하지 않습니다.

브라우저에 저장된 개인 여행 기록은 Git 백업 대상이 아닙니다. 기록 화면의 백업 기능으로 별도 내보내기·가져오기를 이용합니다.
